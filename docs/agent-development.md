## 1. 开发起点、目标与边界

**现在可以开始 Agent 开发，不再以全面优化底座为前置。** 既有接入、转发、带宽实验和恢复工具足以支持 F1/F2 及限定实网接入；组合编排所缺的功能目录与执行适配随具体任务补齐。Dashboard 是观测和发流入口，不是 Agent；其页面完善不构成新的开发前置。

实现一个单 Agent：**理解需求 → 追问缺项 → 查询现场与能力 → 生成受约束方案 → 执行并验证 → 解释反馈与有限调整**。

- 输入：业务描述、明确的用户对象与目标；候选类别为实时交互、持续媒体、后台传输，类别不自动转换为 SLA。
- 过渡接入：复用 [E3](cnf-service-chain-orchestration.md#e3-完整请求与受控策略选择)，先开放双 UE 下行 `equal`、`guarantee-ue1`、`guarantee-ue2`，UDP 30 秒实验，测量后恢复。三模式只证明工具接入闭环，不能作为需求驱动服务链编排的最终验收。
- 最小编排目标：在白名单内，需求与现场状态决定既有中心/边缘服务绑定和带宽控制配置，规划器生成可校验的组合方案，在同一业务路径上执行、测量并恢复。先支持既有实例的绑定与配置；按需创建、迁移和更广的功能链组合属于后续扩展，不据此前者宣称通用编排完成。
- 输出：需求及未知项、方案依据、真实目标比较、恢复结果和证据位置；模拟结果与实网结果明确区分。
- 当前尚未开放：需求驱动的 core/edge 绑定与带宽组合执行，须在 F3b 补接口并验收后才能调用；历史固定配置联合检查不能替代该验收。
- 非当前前置：自主报文识别、原生 5G QoS、多 UPF、任意 CNF 创建、持续在线保障和通用故障修复。不为开始 Agent 开发而全面扩建平台。

### 如何判断超出了实验控制助手

对外表达用户、业务目标、目的地约束和明确带宽目标，而不是要求用户选择实验编号或端口。端口等实现细节由受控映射产生，不能由模型猜测用户身份。

例如：“UE1 的指定业务访问边缘测试服务，下行上限为 5 Mbps”，与仅改变目的地或上限的成对请求，应产生相应的后端绑定或带宽配置差异，且有真实效果证据。这里只验证测试服务接入与限速；最低带宽保障、业务完成时间和时延目标必须按实际能力另行准入，不能从上限推导。

最终至少同时具备：需求驱动配置变化、依赖与能力校验、真实路径与效果验证、失败恢复和可追溯反馈。仅选择三模式、调用脚本、生成解释或增加记忆都不足以单独满足该目标。

## 2. 技术选型

F1 已采用 Python 显式状态机、Pydantic v2、SQLite 与 JSONL 导出；模型 SDK 及实网进程部署仍是后续设计，不属于 F1 已实现能力。

| 部分 | 首版建议 | 作用 |
|---|---|---|
| 语言与运行 | Python 3.10+；实网进程在 VM1 独立虚拟环境运行 | Windows 主工作区开发、测试和审核；VM1 复用现有 kubectl 条件，部署时核对源码哈希 |
| 工作流 | 显式 Python 状态机 | 每个分支、预算与停止条件可读可测；首版不依赖 LangGraph、LangChain 或 Agents SDK |
| 模型 | `ModelProvider` 接口；首个候选为 OpenAI 官方 SDK + Responses API | 其他供应商分别验证适配器，不假定通用兼容；模型 ID 和费用预算待落实 |
| 数据合同 | Pydantic v2 + JSON Schema | 校验需求、动作和返回值；语义来源、容量、会话和权限另行检查 |
| 记忆 | SQLite | 保存会话、需求版本、观测索引和操作记录；首版不引入向量库 |
| 提示词 | 独立文本，职责分为理解、动作选择、结果解释 | 与模型、工具和依赖版本一起归档 |
| 用户入口 | CLI + 中文步骤摘要 | 可查看、继续会话与重放任务；HTTP、MCP、Web 界面及容器部署后续按需评估 |
| 证据 | JSONL 事件 + 原始工具输出 | 可追踪输入、动作、简短决策依据、错误、时间和 token 用量 |

模型接口依据：[Function calling](https://developers.openai.com/api/docs/guides/function-calling)、[Structured Outputs](https://developers.openai.com/api/docs/guides/structured-outputs)。结构化输出仍可能语义错误，不能替代本地校验。密钥只放进程环境或受保护的本地配置，不进入源码、记忆与轨迹；依赖版本在兼容检查后锁定。

## 3. 代码位置与职责

代码统一放在 [`services/cnf_agent/`](../services/cnf_agent/)。下表模块已实现 F1 的离线部分；真实适配与提示词留到后续阶段。

| 文件 | 职责 |
|---|---|
| `__init__.py` | 包入口；导入不触发模型或网络操作 |
| `schemas.py` | 需求、事实、动作、结果及其版本关联 |
| `provider.py` | `ModelProvider` 协议与严格匹配消息序列的 `ReplayProvider`；尚无真实模型调用 |
| `workflow.py` | 状态转换、动作白名单、预算和停止条件 |
| `tools.py` | 四项工具协议及 `SimulatedTools`；F1 只返回声明的模拟能力和结果，尚未加载 E1/E2/E3 脚本 |
| `memory.py` | SQLite 中的会话、需求、观测和任务记录 |
| `trace.py` | 中文模拟标识、结果摘要、JSONL 导出；SQLite 事件为原始记录 |
| `cli.py` | 离线运行、继续会话、展示、导出与开发回放入口 |
| `prompts/`（未创建） | F2 再加入理解、动作选择、解释提示词 |

启动入口为 [`scripts/cnf-agent.py`](../scripts/cnf-agent.py)；测试在 [`tests/test_cnf_agent.py`](../tests/test_cnf_agent.py)，固定开发回放在 [`tests/fixtures/cnf-agent-replay.json`](../tests/fixtures/cnf-agent-replay.json)。原始运行证据放 `results/<日期>-cnf-agent-<实验名>/`，本地数据库默认放忽略目录 `.work/cnf-agent/`。不预建未实现模块。

依赖方向：`CLI → workflow → provider / memory / tools / trace`，统一使用 `schemas`。不复制底层实验脚本；执行工具不反向调用模型，普通收尾不依赖模型在线。

## 4. 运行流程与工具边界

```text
接收需求 → 模型提取 → 来源/缺项/冲突检查
  ├─ 缺项或歧义 → 等待补充 → 新需求版本
  ├─ 不支持 → 解释并停止
  └─ 完整 → 查询现场 → 确定性规划/校验 → 执行、测量、恢复 → 结果解释
状态变化 → 重新查询和规划；执行失败 → 先核对恢复，再决定继续或停止
```

| 工具协议（F1 为模拟实现） | 输入 | 返回与权限 |
|---|---|---|
| `inspect_network` | 允许的查询范围 | 带时间、来源和引用的现场事实及能力边界；配置只读 |
| `preview_policy` | 已校验的需求版本、观测引用 | F3a 返回三模式预览；F3b 才开放经独立验收的组合方案。方案注明能力/适配器版本与执行范围，不授予执行权限 |
| `execute_experiment` | 需求版本、方案引用、运行时操作标识 | 内部完成复验、执行、测量、恢复和严格收尾；不向模型拆开暴露写入与恢复 |
| `get_operation_result` | 已有操作标识 | 操作阶段、目标比较、恢复状态和证据；不能再次启动实验 |

模型理解需求、选择允许的查询并解释反馈；规划器计算容量和模式，状态机裁定动作是否允许，执行器负责现场操作。模型不能直接调用任意命令、kubectl 或 SSH。

功能目录与组合规划/执行接口由 [CNF 模块](cnf-service-chain-orchestration.md#agent-接入与最终交付)维护，至少描述功能职责、镜像、资源、接口、依赖、允许节点、状态及参数范围。iperf3 后端是测试终点；Envoy 同时承担端口分类/代理/静态引导，不能计为三个独立 CNF；当前 tc 依附测试端点，不能声明为任意流量可经过的通用 QoS CNF。

必须落实的控制规则：

1. **来源与绑定**：目标字段可追溯到用户原话或明确应用声明，不补默认 SLA；SUPI/会话来自现场。会话变化产生新观测与新方案，不暗改旧请求。
2. **新鲜度**：澄清和模型调用在锁外；沿用 E3 的状态 TTL 与 30 秒计划起始期限，锁内再次复验。过期重新规划，选择变化先返回，不静默换方案。
3. **操作去重**：写入前记录操作标识与需求版本；同一操作仅一次。超时、重启或回复丢失先查既有操作，无法确认时停止，不能自动重放写入。
4. **恢复与重试**：成功、目标未满足、工具失败、执行失败、恢复失败和结果不明分别表示；工具超时不直接认定网络故障。恢复失败停止写入，不承诺强杀/断电恢复或 exactly-once。
5. **预算**：限制自动推进的模型调用、查询、时间/token 与写入次数，F1 固定配置。F4 再评估一次额外实验，要求前次恢复及严格复验通过、新状态/方案和新操作标识。

记忆保存已确认需求及修改历史、带有效期的观测、方案与操作结果；观测记忆不代替现场查询，模型总结不自动成为已验证知识。轨迹记录公开可核对的简短依据，不要求模型输出隐含推理链。

## 5. 开发顺序与验收

任务设计如下；实际阶段状态仅在[总路线](03-research-roadmap.md#r2-当前阶段顺序)更新。

| 任务 | 交付内容 | 验收重点 |
|---|---|---|
| F1 运行骨架 | 合同、状态机、预算、记忆、轨迹、CLI、回放模型与工具模拟器 | 正常、缺项、冲突、超额和工具错误可重放；能续接会话；明确标注模拟，不计实网或真实模型成功；合同区分需求、能力和方案，不限定为实验编号 |
| F2 真实模型 | 模型适配、提示词、澄清、只读工具 | 字段来源、未知值、多轮修改、会话隔离和预算检查；新留出样例在调试前冻结 |
| F3a 工具接入 | 四项工具与 E3 事务适配 | 三模式及拒绝请求有实际调用、测量和恢复证据；错误格式、重复调用与模型中断不能绕过校验；仅计为过渡闭环 |
| F3b 最小组合编排 | 按任务补齐能力目录、组合规划/校验与执行适配；Agent 调用已有实例的后端绑定和带宽配置 | 成对需求分别改变目的地/带宽目标，方案与实测随之变化；同一业务路径核对正确后端、带宽效果和恢复。完整合同、允许参数与判据在实现和正式测试前固定，不能用独立 E3 UDP 结果替代 Envoy 路径验收 |
| F4 反馈与对照 | 在已验收组合能力上完成有限重规划、配对场景、消融与统计 | 相同工具/权限/校验器下比较规则、普通 Agent、增强方案；统计任务完成、错误操作、目标满足、恢复和开销。只有三模式时仅报告过渡原型结论 |

F1/F2 不下发网络配置，F3 使用明确实验模式。首批场景还须覆盖不支持 SLA、旧会话、过期观测和重复执行；同时统计合法任务完成，避免“全部拒绝”虚高。记录目标满足、错误写入、恢复、查询数、模型开销与时间，核心结果由工具证据判断。研究样例、成功定义、模型和预算在批次前固定。

推进顺序为 **F1 → F2 → F3a → F3b → F4**。F1/F2 期间可设计和离线验证 F3b 的接口，不必等完整 S4 验收再启动 Agent；任何新增现场写入能力仍须先通过底层专项验收。SSH/集群不可达阻止实网写入，不阻止本地骨架开发；实网执行前重新核对现场，不能把 Dashboard 缓存当作执行依据。

## 6. F1 使用与验证

### 运行与回放

在仓库根目录、Python 3.10+ 环境运行；依赖锁定于 [`requirements.txt`](../services/cnf_agent/requirements.txt)，F1 不需要模型密钥、SSH 或集群连接：

```powershell
python -m pip install -r services/cnf_agent/requirements.txt
python scripts/cnf-agent.py demo --replay tests/fixtures/cnf-agent-replay.json --scenario normal
python scripts/cnf-agent.py demo --replay tests/fixtures/cnf-agent-replay.json --scenario missing
python scripts/cnf-agent.py schema
```

全部输出、观测、方案和结果均标为模拟。`demo` 按固定消息及提取结果回放，不是自主自然语言理解；`normal` 也不是实网编排验收。11 个开发场景覆盖正常、多轮补充、冲突、超额、不支持 SLA、查询失败、执行失败、目标未满足、恢复失败、执行回复丢失和结果不明。`demo` 的退出码 0 表示符合该场景的预期状态，可能是预期拒绝/失败，必须同时读取状态。

分开进程继续同一会话（替换打印出的会话 ID，消息须与固定回放一致）：

```powershell
python scripts/cnf-agent.py run --replay tests/fixtures/cnf-agent-replay.json --scenario missing --message "用户 ue1。"
python scripts/cnf-agent.py run --replay tests/fixtures/cnf-agent-replay.json --scenario missing --session <会话ID> --message "补充：video 业务，downlink 方向，访问 edge，上限 5.0 Mbps。"
python scripts/cnf-agent.py show <会话ID>
python scripts/cnf-agent.py export <会话ID> --output results/<新文件名>.jsonl
```

已有操作结果不明或执行阶段中断时，省略消息只查询原操作，不能用新消息触发重跑：`python scripts/cnf-agent.py run --replay tests/fixtures/cnf-agent-replay.json --scenario result_unknown --session <会话ID>`。恢复失败不自动重试；预算耗尽也不绕过限制，须人工核对。`show` 只展示数据库中的已知状态，不查询工具。

全局参数 `--db <SQLite路径>` 放在子命令前，可隔离实验。JSONL 导出拒绝覆盖已有文件。事件保留消息、每版需求、工具输入引用、返回结果及用量；没有模型密钥或环境变量采集。`schema` 输出包括需求、能力、方案和结果的 JSON Schema。

### 状态与停止规则

| 触发与步骤 | 后续状态/行为 |
|---|---|
| 收到消息 → 回放提取 | 字段须有可核对的消息 ID 和原话引用；缺项、冲突或歧义进入 `waiting_input`，不查询或执行 |
| 查询模拟现场 → 预览 | 不支持、超额、过期或绑定不一致进入 `rejected`；不执行 |
| 方案通过 → 调用模拟执行 | 先原子记录操作标识与需求版本的唯一执行占位；并发更新通过 SQLite 版本比较拒绝 |
| 已返回操作结果 | 分别记录 `succeeded`、`failed`、`restore_failed`、`result_unknown`；成功要求模拟检查通过且模拟恢复确认 |
| 超时或执行阶段进程中断 | 继续时只查询原操作；不自动重新执行；结果不明/恢复失败时拒绝新写入需求 |
| 预算耗尽 | `budget_exceeded`，保留已有操作标识和事件；不启动下一次调用，未确认操作须人工核对 |

F1 默认会话累计预算为 4 次模型调用、6 次查询/预览/结果查询、1 次模拟实验、20 次外部调用步骤、4096 个回放 token、60 秒调用累计耗时。用户补充消息不重置预算；人工等待不计入耗时。时间预算在调用前后协作检查，不能中断挂起的真实 I/O；F2/F3 的适配器仍须配置实际超时。恢复责任留在事务工具，不能依赖下一次模型调用。

原话引用检查仅证明来源字符串存在，不证明模型语义理解正确；回放 token 是固定测试用量，不是实际计费。模拟器操作结果只保留在当前进程内，跨进程查不到已发起操作时保持结果不明；SQLite 保存的已确认结果可正常重读。这不是已实现真实崩溃恢复或 exactly-once。
