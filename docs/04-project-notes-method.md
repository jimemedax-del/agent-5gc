# 项目记录方法：让聊天、实验和论文材料持续沉淀

> 最后更新：2026-10-08

## 原则

不要保存“完整聊天转录”。应保存能在未来支撑复现、写论文、汇报或求职的四类事实：

1. 做出了什么决策；
2. 用什么环境和配置做了实验；
3. 得到了什么证据；
4. 下一步还缺什么。

## 文档层次

遵守根目录 [AGENTS.md](../AGENTS.md) 的文档边界：按模块更新已有文档，不按操作步骤递增编号。下表是内容归类，不要求为每次实验、决策或文献新建文件；下方模板默认作为模块文档内的章节使用。

| 类别 | 建议位置 | 记录什么 |
|---|---|---|
| 项目总览 | `README.md` | 目标、阶段、入口与状态 |
| 领域理解 | `docs/02-*.md` | 心智模型、术语、架构图 |
| 实验记录 | 已有模块文档；原始数据放 `results/` | 环境、命令、配置、结果、失败原因 |
| 决策记录 | 对应模块文档的决策章节 | 为什么选 A 而不选 B |
| 文献记录 | 已有研究文档的文献附录 | 问题、方法、实验、可借鉴点、不可照搬点 |

不因进入新阶段自动创建目录或独立文档。仅在出现独立模块、现有文档无法容纳且用户确认后新增；不为目录整齐提前放空文件。

## 每次实验的最小模板

```markdown
# EXP-YYYYMMDD-简短名称

## 目标
要验证什么？成功标准是什么？

## 环境与版本
VM、系统、镜像、配置提交或文件路径。

## 操作
只保留能复现的关键命令；敏感信息不写入仓库。

## 结果与证据
关键输出、截图位置、指标与是否通过。

## 结论
[已验证] / [失败] / [不确定]

## 下一步
一个明确可执行的动作。
```

## 每次技术决策的最小模板

```markdown
# ADR-001：选择 free5GC Compose 作为单机基线

## 背景
需要先理解 5GC 端到端流程。

## 决策
选择 free5GC Compose v4.2.2 + UERANSIM v3.3.0。

## 原因
可以更快跑通注册、PDU Session 和用户面；Kubernetes 留给下一阶段。

## 后果
该环境不能证明多节点 NF 放置，也不能替代最终 Helm/Kubernetes 评测。
```

## 文献统一模板

每篇文献控制在一页左右：

1. 文献信息及研究问题；
2. 核心架构与方法；
3. 实验设置和结论；
4. 与本项目的契合点；
5. 可直接借鉴的设计；
6. 不可直接照搬的部分；
7. 对项目计划的具体影响；
8. 适合作为相关工作、方法依据还是对照实验。

## 更新触发条件

出现以下任一情况就更新文档：

- 组件版本、镜像、网络配置或运行拓扑改变；
- 一个流程从“推测”变为“验证成功/失败”；
- 与导师确认了研究边界或指标；
- 新增了能影响方案设计的文献；
- 做出了难以反悔的技术选择。

文档只记录可信结论。未验证的内容必须标记为 `[待验证]` 或 `[待确认]`，这样它既是学习笔记，也是未来论文的证据链。
